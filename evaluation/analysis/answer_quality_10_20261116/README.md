# 10 个历史样本的 Proxy 回答充分性分析与标注

本次对两轮已完成的 grounded-v1 实验进行回顾，分析最终真正交给 Agent 的回答。标注由当前 Codex 模型逐题对照完整来源完成，尚未经过独立人工或第二位评审复核；没有额外调用外部 Judge API。生成脚本仅导出显式标注决定、校验引用和计算统计，不自动判断答案质量。

## 数据和统计口径

- 前 3 例来自 qwen-proxy-grounded-v1-20261029，新增 7 例来自 qwen-new7-grounded-v1-20261101。
- 共 10 批初始问答，42 道编号问题，30 条成功保存的 Proxy 回复；其中 20 条仅确认进度，不纳入回答质量分母。
- 标注使用最终交付答案，不用复核前的原始 draft；丢弃、失败及重试问答不混入这 42 道问题。
- 每题单独记录，但判断时可见同批其他答案；共享事实不能重复宣称为独立信息增量。
- 缺失的 Hints/files 中字符串 nan 统一视为空；原文的重复段落、乱码不当作新事实。

## 标注标准

| 维度 | 标签与含义 |
| --- | --- |
| 真实性 | supported：来源支持；mixed：正确内容与无依据/过度确定化混合；conflicting：违背后期明确来源 |
| Incomplete | 来源能提供、与当前所问直接相关且影响行为或验证的关键事实未被回答；不因没有复述全部 issue 而标记 |
| Ambiguous | 结合整批回答后仍有两种以上合理且行为不同的解释；不把一般不够详细、实现方法多样自动算作需求歧义 |
| 来源可答性 | available：当前所需事实有来源；partial：只有部分子项或有保留意见；unavailable：所求具体信息没有来源 |
| 回应程度 | direct：直接回应；partial：未回答部分子项、改答相关根因，或未明确说明未知部分 |

以上标签可重叠。supported 不等于充分；source-limited 不等于 Incomplete；后续修复失败也不自动意味着回答不充分。原文没有明确的兼容规范、精确版本或复现代码时，不用隐藏测试倒推应答要求。

### 边界标注的敏感性

五个优先复核项是：12907 Q3、13579 Q3 的完整性；13398 Q6、8872 Q3、10880 Q4 的真实性。它们分别涉及精确判据是否属于当前问题必须交付的信息、历史讨论是否被当成当前约束、以及概括/版本指代是否过强。

若将这些边界标记全部取消，Incomplete 为 7/42，真实性问题为 5/42，Ambiguous 仍为 3/42，至少一种问题的去重数为 8/42。这是标注尺度的敏感性分析，不是第二位评审的独立标注结果。

### 来源不足与回答不充分的区别

来源可答性分布：available=31；unavailable=3；partial=8。

- 12907 Q4、8707 Q3、10880 Q2：来源分别没有具体已有测试、bytes traceback/反例、最小 Count/Case 代码；不能把这些全部算作可通过追问恢复的信息。
- 13033 Q4：Hints 有 test_common.py 的导航线索，但没有明确指出专门复现此 bug 的已有用例；标为部分可答，不把缺少特定测试名算作关键需求遗漏。
- 10097 Q2：正确非法 URL 已给出，但反向合法却被拒绝的例子原文没有；未明确说未知属于部分回应。
- 10880 Q4：回归提交有依据，最后正常版本没有；“Django 2.2 之前/之内”的具体解释需谨慎，当前轻度真实性标注应优先人工复核。

### Agent 是否继续澄清

检查保存的 102 条修复阶段 Agent 纯文本消息，未观察到面向用户的针对性追问。唯一带问号的候选是 8872 事件 186 中的自我诊断 “But what is dtype at this point?”，不是请求用户补充信息。

20 条成功交互中的后续消息都是进度说明，且同样消耗原有三次回复预算。因此能陈述“这些轨迹没有完成针对缺口的追问闭环”，但不能仅据此归因模型不具备识别能力；流程设计和回复预算也限制了追问。完整修复阶段消息见 solver_message_review.json。

## 适合作为 Motivation 的案例

### 10554 可回答的信息被遗漏

Proxy 的最小复现在首次打印 qs 后结束。完整 issue 明确还包含求值 qs.order_by().values_list('pk', flat=True) 后再次求值原 qs 的步骤。这是比泛泛要求“多给些信息”更明确的追问目标。原文示例本身有括号不完整等问题，不能全部归咎 Proxy；关键触发链被删去则可以直接核实。Agent 后续尝试复制 query，但复现遇到语法、配置、建表问题；这些观察不能证明补齐回答必然修复成功。

### 12907 定性回答正确仍可能缺少验证判据

Proxy 正确说独立分量在嵌套后仍应独立，却没有传达来源中的精确预期矩阵。事件 87 显示 Agent 将正确的右下对角块误判为应全 True。这支持为具体反例补充精确输出判据的动机，但不证明原回答在逻辑上有两种合理需求解释，也不能证明有矩阵就必然避免推理错误。该例最终官方 resolved 为 True，不能将中途误判写成最终失败。

### 13398 不完整与不真实必须分开

Q3/Q5/Q6 延续早期忽略时间或警告讨论，Q7 将范围限于 ITRS/Observed；后期 Hints 已转向 actual topocentric ITRS，并明确涉及 ICRS/CIRS/TETE。同一批回答同时存在最终方向遗漏、历史方案状态混淆及警告/异常分支未定。事件 132 的修改采纳旧方向并加入 UserWarning，说明错误信息确实有被采用的风险，但这里是回答纠正与补充的混合问题，不适合作为纯 Partial 条件的唯一证据。

### 13236 充分回答与正确停止的正例

历史回答已完整传达直接创建 Column、立即改变且无需 FutureWarning，纠正了问题自带的旧前提。这例历史数据不能写成“Proxy 原本回答不完整”。若后续将其用于 Partial 实验，必须明确是新构造的受控回答缺口，并保留该历史充分回答作参考。

## 对下一步初测的具体影响

- 保留 12907、13236、10554 的实验选择，但明确 13236 是充分回答正例与后续受控 Partial 素材。
- 核心任务区分为：补充可回答遗漏、识别无依据或过期信息、对来源不足正确停止。
- 当前严格 Ambiguous 标签集中在 13398 的同批警告/异常选择，不能宣传为普遍存在的残余需求歧义。
- 先用以上标注定义充分性检查项，再设计 Partial 策略，避免为了展示追问收益而把每个答案都判为不足。

## 限制和复核建议

这是单模型辅助的第一版标注，全部 42 条仍需独立人工复核；机械引用匹配只验证摘录确实存在，不验证语义推断一定成立。优先复核 12907 Q3 的“关键验证细节”边界、13579 Q3 的回应范围、8872 Q3 的过度概括以及 10880 Q4 的版本指代。小样本、共享批次、原有进度消息消耗预算、历史运行的导入路径问题和人工操作都会限制因果结论。

未重新运行修复或测试这些历史补丁。后续使用证据沿用已有轨迹，并导出所引事件供检查；不能把后来单独诊断得到的结果冒充 Agent 当时已完成的验证。

此前审计引用过的 13398 事件154 不在所用快照 history 中，本次不沿用该引用；导出的全部事件号均已检查存在。新7例的信息使用说明保留此前逐题审计的来源，并附原有导入路径和人工操作等 caveat，不当作本轮重新执行得到的结论。
